# Boundary Setting Governance

Boundary governance ensures that scope, stakeholders, evidence, responsibility, and revision remain visible throughout strategy development.

## Governance requirements

- Problem boundary statement
- System boundary map
- Stakeholder boundary review
- Causal-frame comparison
- Temporal horizon review
- Institutional authority/influence/consequence map
- Evidence boundary review
- Ethical boundary review
- Boundary-sensitive option evaluation
- Boundary drift log
- Revision-trigger log
- Decision-memory record

## Review cadence

- Before ideation: define current boundary and alternatives
- Before option evaluation: test boundary sensitivity
- Before implementation: review stakeholders, evidence, ethics, and consequences
- During implementation: monitor boundary drift and hidden burdens
- Before scale: confirm that the boundary still fits the problem
- After implementation: update decision memory and revision triggers

## Anti-failure rules

- Do not treat the initial boundary as neutral.
- Do not let the organization chart define the consequence boundary.
- Do not score options before testing boundary sensitivity.
- Do not exclude affected stakeholders for convenience.
- Do not treat metrics as the whole evidence boundary.
- Do not let boundary revision happen without documentation.
