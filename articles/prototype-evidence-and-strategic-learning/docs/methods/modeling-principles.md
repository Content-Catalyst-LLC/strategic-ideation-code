# Modeling Principles for Prototype Evidence and Strategic Learning

## 1. Treat prototypes as learning instruments

A prototype should answer a learning question. It should not merely persuade, impress, or create momentum.

## 2. Test critical assumptions first

Prioritize assumptions that are uncertain and consequential.

## 3. Match prototype fidelity to the learning target

Use the lowest useful fidelity for the uncertainty being tested.

## 4. Define evidence before testing

Teams should define support, challenge, and inconclusive evidence before results arrive.

## 5. Observe behavior, not only opinion

Stated preference matters, but behavior reveals commitment, friction, trust, workarounds, and contextual barriers.

## 6. Interpret evidence within limits

Every prototype has boundaries. Document what the evidence does and does not support.

## 7. Look for systems effects

Prototype evidence should be interpreted for feedback loops, delays, burden shifts, capacity constraints, incentives, and scale conditions.

## 8. Link evidence to decisions

Evidence should change something: continue, revise, pause, stop, scale, reframe, or test again.

## 9. Preserve learning memory

Prototype evidence should leave a reusable record of assumptions, tests, evidence, interpretation, decisions, limits, and remaining uncertainty.
