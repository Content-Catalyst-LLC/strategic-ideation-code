# Theory of Change Governance

Theory-of-change governance ensures that strategic logic remains visible, testable, and revisable during ideation, prototyping, implementation, and evaluation.

## Governance requirements

- Problem frame and boundary statement
- Mechanism statement
- Causal link map
- Assumption register
- Evidence match review
- Actor response map
- System feedback review
- Outcome sequence map
- Prototype test plan
- Implementation learning loop
- Revision-trigger log
- Decision-memory record

## Review cadence

- Before option selection: review strategic logic and causal links
- Before prototype: define which link or assumption the prototype tests
- Before pilot: define success thresholds and failure decisions
- Before scale: review evidence transferability and system response
- During implementation: monitor actor response, burden shifts, and feedback loops
- After implementation: update decision memory

## Anti-failure rules

- Do not confuse activities with outcomes.
- Do not let arrows hide assumptions.
- Do not claim impact from outputs.
- Do not assume actors will respond as intended.
- Do not ignore feedback loops, delays, or burden shifts.
- Do not collect evidence that does not test the causal claim.
- Do not let learning fail to change decisions.
