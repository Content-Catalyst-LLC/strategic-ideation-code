# Problem-Framing Governance

A professional problem-framing process should govern how teams construct, compare, test, revise, select, and remember problem definitions.

## Governance requirements

- Current problem statement
- Frame-origin review
- Boundary audit
- Stakeholder frame map
- Causal model
- Assumption audit
- Alternative-frame comparison
- Success criteria
- Reframing trigger
- Decision-memory record

## Review cadence

- Before ideation: define the current frame and origin
- Before solution generation: compare rival frames
- Before prototype selection: test boundary, stakeholders, causality, and assumptions
- Before implementation: define success criteria and reframing triggers
- After implementation: revise the frame when evidence contradicts the definition
- Quarterly: review archived frames and reopened assumptions

## Anti-failure rules

- Do not accept the first plausible frame as final.
- Do not treat administrative categories as causal truth.
- Do not let a preferred solution define the problem.
- Do not ignore affected stakeholder definitions.
- Do not allow weak frames to become institutionally protected.
- Do not forget why a problem definition was chosen or rejected.
