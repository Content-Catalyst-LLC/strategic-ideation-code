# Problem-Framing Workshop

## Purpose

Help a strategy team define the right problem before generating solutions.

## Suggested duration

2 to 3 hours.

## Participants

- Strategy lead
- Facilitator
- Analyst or evidence lead
- Stakeholder researcher
- Systems thinker
- Frontline or implementation owner
- Governance owner
- Decision-memory owner

## Agenda

### 1. State the current frame

Write the current problem definition in plain language.

### 2. Identify the frame origin

Ask where the problem definition came from: leadership, metrics, crisis, stakeholder evidence, frontline evidence, legacy categories, or a preferred solution.

### 3. Test the boundary

Identify who and what is inside and outside the definition.

### 4. Map stakeholder definitions

Ask how affected groups, frontline workers, technical teams, leaders, and governance owners define the problem differently.

### 5. Examine the causal story

State the assumed mechanism. Is the problem caused by trust, incentives, behavior, capacity, information, governance, systems structure, or something else?

### 6. Surface assumptions

List what must be true for the frame to hold.

### 7. Generate rival frames

Develop at least three alternative definitions and compare their implications.

### 8. Select a working frame

Choose a working definition, not a permanent truth.

### 9. Define reframing triggers

Identify evidence that would cause the team to reopen the definition.

### 10. Preserve decision memory

Record what was chosen, rejected, deferred, and why.

## Output

- current problem statement
- frame-origin note
- boundary map
- stakeholder frame map
- causal mechanism statement
- assumption audit
- frame comparison matrix
- reframing trigger log
- decision-memory record
