# Modeling Principles for Problem Framing and Problem Definition

## 1. Treat frames as constructed representations

A frame is not reality. It is a selective model of reality for action.

## 2. Compare frames before selecting one

Do not allow the first plausible problem definition to govern strategy before rival frames are considered.

## 3. Separate administrative convenience from causal accuracy

Existing reports, departments, metrics, and budget categories may be convenient but may not reflect the real problem structure.

## 4. Test boundaries deliberately

Problem boundaries determine which causes, stakeholders, consequences, and time horizons are visible.

## 5. Make assumptions explicit

Every frame contains assumptions about causality, responsibility, value, feasibility, and success.

## 6. Include stakeholder definitions

Affected stakeholders may define the problem differently from leadership, technical teams, or analysts.

## 7. Build reframing triggers

Frames should be reopened when evidence, implementation, stakeholder feedback, or systems behavior contradicts the definition.

## 8. Preserve decision memory

Record why frames were chosen, rejected, revised, or archived.
